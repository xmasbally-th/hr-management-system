**ใบลาที่ใช้:** VACATION `71e9e1d4` (สายวิชาการ ผ่านขั้นประธานสาขามาแล้ว)

## ผลการทดสอบ

| ขั้น | พฤติกรรมที่สังเกต | ผล |
|---|---|---|
| คณบดีลงนาม → approved | ปุ่ม 3 ทางโผล่: สแกน / ส่งมหาวิทยาลัย / จบที่คณะ | ✅ |
| สแกน+อัปโหลด (ไฟล์ PDF จริง 238 KB) | toast สำเร็จ · timeline ลงเวลา "สแกน + อัปโหลดเอกสาร (ระดับคณะ)" + ลิงก์ "ดูไฟล์" | ✅ |

## ความปลอดภัยที่ยืนยันจากโค้ด (storage-actions.ts)
- อัปโหลด/ลบ จำกัด HR/Admin เท่านั้น (`checkHrAdmin`) + rate limit
- จำกัดชนิดไฟล์ (PDF/JPG/PNG/WebP) + ขนาด ≤ 5MB
- เข้าถึงไฟล์ผ่าน signed URL อายุ 1 ชั่วโมง (ไม่ public)

## 🟡 ประเด็นที่พบ (จุดวิเคราะห์ต่อ)
**ชื่อไฟล์ภาษาไทยถูก sanitize จนเสียความหมาย** — `storage-actions.ts:62`
ใช้ `replace(/[^a-zA-Z0-9._-]/g,"_")` ทำให้ "ลาพักผ่อน.pdf" กลายเป็น
`1781147803215-_________.pdf` และ "ลาพักผ่อน-อธิการบดีลงนาม.pdf" เป็น
`...-_________-______________.pdf`
- ไม่กระทบการทำงาน (ระบบอ้างด้วย path + timestamp ไม่ชนกัน)
- แต่ HR แยกไฟล์จากชื่อไม่ได้เลยเมื่อดูใน storage/รายการเอกสาร
- **แนวทางแก้ที่เสนอ:** เก็บชื่อเดิมไว้ในคอลัมน์ metadata หรือ
  transliterate/อนุญาตอักษรไทยใน key (Supabase storage รองรับ UTF-8 keys)
